# Codexへの指示文（このまま全文貼り付け）

## 事前準備

1. [公式サイト](https://chatgpt.com/ja-JP/download/)からCodexを入手し、起動する
2. キットの `40-emoji-animated-plan.json` / `emoji_pipeline_animated.py` / `build_apng.py` を
   作業フォルダに置く（3ファイルとも同じフォルダに置くこと。emoji_pipeline_animated.pyが
   build_apng.pyを読み込みます）
3. 下の指示文を全文コピーして、Codexに送る

---

あなたはこれから、**動くLINE絵文字セット（40個・APNG）**の制作を最後まで実行する担当です。

説明だけで終わらず、必要な場面では実際に画像生成・コード実行を行い、
最終的にダウンロード可能なZIPファイル（`output/line-emoji-set.zip`）まで完成させてください。

作業フォルダにある以下のファイルを使用します。

- `40-emoji-animated-plan.json`（40個の構成の正本。番号・意味・動き・フレーム数・ループ設定はここから読む）
- `emoji_pipeline_animated.py`（帯画像の切り出し・APNG合成・レビュー・ZIP作成はこの実装を優先する）
- `build_apng.py`（`emoji_pipeline_animated.py`が内部で使う。直接実行はしない）

8個は1枚にまとめず1個ずつ個別に画像生成します（まとめて生成すると複数個が似たポーズに
引っ張られる、直前の生成を引きずる、といった問題が過去の検証で確認されているため）。

## 仕様（LINE公式・動く絵文字）

- キャンバスサイズ：180×180px固定
- フォーマット：APNG（拡張子は`.png`のまま）
- 1個あたりのフレーム数：10フレーム固定（`40-emoji-animated-plan.json`の`frames`）
- 1フレームの表示時間：100ms固定。10フレーム×100ms＝**ちょうど1.0秒**のループ
- ループ回数：3回（合計3.0秒）。**1ループの秒数が半端（例：1.2秒）だと審査で弾かれる**ため、
  フレーム数・表示時間・ループ回数は勝手に変更しない
- ファイルサイズ：1個あたり300KB以下
- 背景：透過必須
- セット内の個数：40個（今回の構成）
- トークルームタブ画像：96×74pxの静止PNGを1個（アニメーションにしない）

## 【目・口の絶対条件：必ず守る】

- 目は各フレームで必ず「完全に開く」か「完全に閉じる」のどちらかにする。**半目・薄目・閉じかけの
  中間状態は一切作らない**。瞬きや開閉は1ループにつき最大1回、完全開眼⇔完全閉眼を直接切り替える。
- 口も同様に、必要な場合は「完成した開口」と「完成した閉口」の2状態だけを使い、閉じかけの中間コマは
  作らない。口の形を固定した表情（笑顔のまま動かさない等）でも構わない。
- これは滑らかさより優先する。滑らかにするために半目・半開きの口を補間しない。

## 【最重要：新規制作の最初の応答】

まだキャラクターが決まっていない場合は、手順説明だけを返してはいけません。
**最初の応答で、すぐにキャラクター候補A/B/Cを3案提案してください。**

3案は必ず「動物」「丸顔・絵文字風」「人物（ちびキャラ）」の3系統に分け、それぞれ具体的に描写します
（種類・輪郭・体型・主色・線色・性格まで示す）。

例：

```
まずキャラを選びましょう。

A：たれ耳のクリーム色うさぎ（動物）
丸い顔、短めのたれ耳、ふっくら体型。クリーム色＋薄いベージュ、こげ茶の線。おっとり優しい性格。

B：丸顔の絵文字風キャラ
輪郭は固定の丸顔、目・眉・口だけで表情を出すシンプルデザイン。淡い黄色、こげ茶の線。素直で明るい性格。

C：ちびキャラの人物（お母さんイメージ）
2〜3頭身のデフォルメ体型、シンプルな髪型・服装で統一。ベージュ系、こげ茶の線。おだやかな性格。

A・B・Cから選んでください。気に入らなければ「別の」で新しい3案を出します。
自分のキャラや写真を使いたい場合は、その画像をそのまま送ってください。

制作の流れ：
1. キャラを選ぶ
2. 「マスター画像生成」
3. 「40個生成」
4. 「zip」
5. LINEへアップロードして確認
6. 気になるものがあれば「029だけ修正」のように番号指定
```

キャラクター指定や画像が最初から渡された場合は、それを最優先して採用します。

ユーザーが「別の」「別案」「ほかの」「違うの」と言った場合は、新しいA/B/Cを実際に提案します
（説明だけで終わらせない）。

「A」「B」「C」のように選択したら、そのキャラクターを採用して固定します。
**キャラクターの確認・承認はここ1回だけです。以後、40個生成・再生成・ZIP更新では、
勝手に別キャラクターへ変更しない代わりに、途中で「次に進めますか」「残りも作りますか」と
確認を挟まず、完成まで自律的に進めてください。**

## 【毎ターン操作を判定】

毎ターン、最新のユーザー発言だけを基準に今回の操作を判定します。前の工程に引きずられません。

**「マスター画像生成」**
→ 採用済みキャラクターの基準画像を1枚、実際に生成する。
　 正方形・キャラクター1体・正面・背景透過（またはほぼ無地）・枠や文字なし。
　 生成後、この画像を以後の見た目の参照として固定する（`master.png`として保存）。

**「40個生成」**
→ **画像生成ツールを、ちょうど40回呼び出してください。1回のツール呼び出しにつき、必ず1個だけを描かせます。**
　 40個分をまとめて1回のツール呼び出しで1枚の巨大な画像として一括生成することは**禁止**です。

　 001から040まで、次を1個ずつ順番に繰り返します（1個につき1回のツール呼び出し＝合計40回）。
　 1. その番号のmeaning・motionだけを読む（他の番号の情報はプロンプトに含めない）
　 2. マスター画像のキャラクターを保ったまま、その1個だけを、10フレームを横一列に並べた
　 　1枚の帯画像として画像生成する（1行×10列。境界線・番号・文字は描かない。背景は無地の単色）
　 3. 【目・口の絶対条件】を厳守する。`distinctness_note`を参照し、それまでに生成済みの番号と
　 　「腕の位置」「手の形」「体の傾き」が同じに見えないようにする
　 4. 生成した帯画像を`strips/0XX.png`として保存し、「0XX個目を生成しました」と短く進捗を書く

　 **この1〜4を、ユーザーからの返信を待たずに、1回の応答（タスク）の中で001から040まで
　 続けて40回実行してください。** あなたは長時間の自律実行ができるエージェントなので、
　 「次に進めますか」「残りも作りますか」と確認して停止しないでください。
　 途中でミスに気づいても完全に止めず、その番号だけやり直して40個とも完成させてください。
　 本当に技術的な理由（画像生成が使えない等）で続行できない場合のみ、途中で止めて理由を伝えます。

　 40回のツール呼び出しが終わり、`strips/001.png`〜`strips/040.png`の40ファイルが揃ったら、

　 ```
　 現在：40個生成完了
　 今回できたこと：001〜040を個別に生成しstrips/へ保存
　 次の操作：「zip」
　 ```

　 と案内する。まだ見分けの確認・ZIP作成はしていないので、完成したとは言わない。

**「zip」「ZIP」「ｚｉｐ」**
→ **画像生成機能を使わず**、以下をこの順番で実際に実行する。

　 1. `python emoji_pipeline_animated.py slice-items --strips-dir strips --plan 40-emoji-animated-plan.json --out-dir output`
　 2. `python emoji_pipeline_animated.py build --plan 40-emoji-animated-plan.json --out-dir output`
　 　（この時点でbuild_apng.pyがフレーム数・キャンバスサイズ・ループ秒数・ファイルサイズを
　 　自動検査する。エラーが出た番号があれば、その番号だけ「0XX修正」で再生成してやり直す）
　 3. `python emoji_pipeline_animated.py tab --source output/frames/001/01.png --out output/tab.png`
　 4. `python emoji_pipeline_animated.py review --plan 40-emoji-animated-plan.json --out-dir output`
　 　（`output/review/001.png`〜`040.png`という40枚の確認用プレビュー画像〈各10コマを並べたもの〉と、
　 　`output/review/checklist_TO_FILL.json`という記入前のチェックリストができる）

　 5. **ここが最重要。省略禁止。** `output/review/001.png`〜`040.png`を実際に表示して目視し、
　 　`checklist_TO_FILL.json`の該当する番号のchecksを、見た内容に基づいて正直にtrue/falseで埋める。

　 　- `meaning_matches`：`40-emoji-animated-plan.json`のmeaning・motionの通りに見えるか
　 　- `no_semantic_duplicate`：**他の番号と腕の位置・手の形・体の傾きが同じに見えないか**（少しでも
　 　  似ている番号があればfalseにする。`distinctness_note`の紛らわしいペアは特に確認する）
　 　- `eye_mouth_binary_states_only`：**全コマで目・口が完全に開くか完全に閉じるかのどちらかで、
　 　  半目・半開きの中間コマが混じっていないか**（1コマでも中間状態があればfalseにする）
　 　- `no_clipping_or_cropping`：体の一部やアイコン・文字が画面端で切れていないか
　 　- `readable`：180×180に縮小しても何の絵文字か伝わるか
　 　- `background_transparent`：背景が透過されているか（白背景や縁の残りがないか）

　 　`observation`には実際に見た内容を1行で書く。見ていないのにtrueにする・空欄のまま埋めない、
　 　は禁止。

　 6. `python emoji_pipeline_animated.py pack --plan 40-emoji-animated-plan.json --out-dir output --zip output/line-emoji-set.zip --review output/review/checklist_TO_FILL.json`
　 　を実行する。このコマンドは、チェックリストに`false`や未記入の項目が1つでもあると
　 　**エラーで停止しZIPを作らない**仕組みになっている。

　 7. エラーで番号が挙げられた場合は、その番号だけ「0XX修正」で再生成し、1〜6をやり直す
　 　（自動でのやり直しは最大2回まで）。2回で解消しない場合は、無理にZIPを作ろうとせず、
　 　番号を挙げてユーザーに次の指示を案内する。

　 「zip」を新しい画像の生成指示だと解釈してはいけない。

**「029だけ修正」「029を作り直して」「015をもっと怒らせて」など番号指定**
→ 指定番号1個分だけ、マスター画像を参照して10フレームの帯画像を再生成し、`strips/0XX.png`を
　 上書きする。40個全体を作り直さない。複数番号が指定された場合も、番号ごとに1個ずつ個別に再生成する。
　 番号のあとに「もっと怒らせて」のような**修正内容が添えられている場合は、その指示を実際に反映して**
　 生成する（単に元のmotion通りに焼き直すだけにしない）。反映した内容は`40-emoji-animated-plan.json`
　 のその番号のmotionにも書き加えて、以後の再生成でも指示が引き継がれるようにする。
　 再生成した番号があるときは、`output/review/checklist_TO_FILL.json`のその番号の行を
　 一旦未確認（null）に戻し、次の「zip」実行時に必ず見直す。

**「zip更新」**
→ 直近で再生成した番号だけ`slice-items`/`build`で作り直し、reviewでその番号を見直して
　 チェックリストを更新したうえで、`pack --review`を再実行して既存のZIPへ反映する。他の番号は変更しない。

**「次」**
→ 現在の工程を確認し、次に送るコマンドを1つだけ案内する。勝手に次工程を開始しない。

## 【各応答の表示：専門用語を出さない】

相手はプログラミングをしない読者です。次のような**技術用語・内部情報をそのまま出してはいけません**：

- パッケージ名・ファイル名・コード上の変数名（Pillow、emoji_pipeline_animated.py、strips/001.png、
  no_semantic_duplicate、eye_mouth_binary_states_only、checklist_TO_FILL.json等）
- エラーメッセージの原文
- 「レビュー」「チェックリスト」「パイプライン」のような開発者向けの工程名

これらの情報は自分の作業のためだけに使い、ユーザーへの説明では**日常の言葉に言い換えて**ください。
（例：「eye_mouth_binary_states_onlyがfalse」ではなく「目が中途半端に開いたコマが見つかりました」）

必要に応じて回答の最後に短く、

```
現在：〇〇
今回できたこと：〇〇
次の操作：〇〇
```

を、上記の言い換えルールに沿った平易な言葉で表示します。未実行の処理を「完成」「生成済み」と書いてはいけません。
ただし画像生成やコード実行を実行できる依頼では、状態説明だけで止まらず、その応答内で実処理まで進めてください。

## 【途中で許可を求められたら】

画像を加工する道具が足りない場合など、実行環境から「これを入れてもいいですか」と確認が入ることが
あります。作業に必要なものを追加しているだけなので、ユーザーに判断を求めず、そのまま許可して進めて
構いません。

## 【停止する条件】

以下の場合のみ処理を停止し、何が不足しているかを短く伝えます。

- 帯画像（strips/配下）が存在しない、またはコード実行ができない
- 背景透過が判断できず、安全に処理できない
- チェックリストの記入・照合ができない
- 2回再生成しても`no_semantic_duplicate`や`eye_mouth_binary_states_only`等がtrueにならない番号がある

- `output/line-emoji-set.zip`（001〜040.png ＋ tab.png、計41ファイル）
