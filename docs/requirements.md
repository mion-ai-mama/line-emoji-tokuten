## 1. プロジェクト概要

Instagramリールの特典として配布する、スマートフォン最優先の1ページ完結ガイド。
「LINE絵文字40個セット（静止画）」をCodex（コード実行ができるAIエージェント）またはChatGPT
（コード実行機能）のどちらでも作れるように、2つのルートを1つのキットとして案内する。

競合LP（one-lp-1.com/lp/line-emoji/）の構成を参考にしつつ、配布するキットの中身は完全オリジナルで新規作成する
（競合が配布するファイルをそのまま流用しない）。

### 成功指標

| 種別 | 指標 |
|---|---|
| 定量 | 横スクロール0件（320 / 375 / 1280px）／JSエラー0件／プロンプトが全箇所ワンタップでコピー可能 |
| 定量 | キットZIPのダウンロードが正常に完了する（GitHub Pages配信・100MB制限内） |
| 定性 | Codexを持たない読者でも「ChatGPTだけ」ルートで最後まで迷わず到達できる |
| 定性 | 自分の絵がない読者も、AIが提案するキャラクター候補（A/B/C）から選ぶだけで迷わず次に進める |
| 定性 | 誇張表現・未確認の断定を含まない |

### 想定読者

AI初心者／副業・個人事業化志向／「絵が描けない」という障壁を感じている層／
Codex利用者とChatGPTのみの利用者の両方／スマートフォンでの閲覧・操作が中心。

## 2. 配布キットの仕様（このページの核）

### 2.1 LINE公式の技術仕様（LINE Creators Market・静止絵文字）

| 項目 | 仕様 |
|---|---|
| フォーマット | PNG（静止画） |
| キャンバスサイズ | 180×180px固定 |
| ファイルサイズ | 1個あたり1MB以下 |
| 背景 | 透過必須 |
| 解像度・カラーモード | 72dpi以上・RGB |
| セット内の個数 | 「絵文字」のみのパッケージで8〜40個（1個単位で調整可） |
| メイン画像 | セットの中から4個を選ぶ（ストア掲載用） |
| トークルームタブ画像 | 96×74px を1個 |
| 提出用ZIP | 全体で20MB以内 |
| 出品 | LINE Creators Marketへの個人登録・申請は無料（審査あり） |

> 2026-09-21修正: キャンバスサイズを「320×270px以内」→「180×180px固定」に訂正
> （LINEスタンプ側の仕様と混同していた誤り。公式ガイドライン
> [creator.line.me/ja/guideline/animationemoji](https://creator.line.me/ja/guideline/animationemoji/)
> で確認済み）。あわせてセット個数・メイン画像・タブ画像の仕様を追記した。
>
> 2026-09-22改訂: 静止画方式への刷新に伴い、フォーマットをAPNG→PNGに、
> フレーム数・ループ回数・再生時間の項目を削除、ファイルサイズ上限を300KB→1MBに変更した。

### 2.2 制作フロー（競合の会話駆動パイプラインを踏襲）

> 2026-09-21改訂: 当初は「モチーフを選んでコピペ→表情差分を1個だけ作る」設計だったが、
> 競合プロンプト（LINE静止絵文字40個の自動生成パイプライン）と比較した結果、
> ①LINEは8〜40個の**セット**出品が前提であること、②ChatGPT/Codexの
> コード実行機能を使えば画像生成からZIP作成まで**同一チャット内で完結**できることが判明したため、
> 1個だけを手作業で作る設計から、**8個セットを会話駆動で一括生成する設計**に全面刷新した。

> 2026-09-22改訂（静止画40個への全面刷新）: 上記の「動く絵文字8個セット（APNG）」を
> 実機（ChatGPT）で繰り返し検証した結果、次の不具合が解消できなかった：
> ①8個を1枚のグリッドで同時生成すると複数個が似たポーズに引っ張られる、
> ②1個ずつの個別生成に変更しても、直前に生成した1個の画像を引きずって次の番号が
> 同じポーズになる、③apngパッケージ依存によるZIP作成エラー（Pillow単体方式に修正済みだが、
> 上記①②は指示文の工夫では解消しなかった）。
>
> 一方、競合の「静止画40個セット」を同条件で試したところ、1回の生成でほぼ完成に近い
> 精度が得られた。静止画は6フレームの動き一貫性を要求しない分、生成タスクとして
> 本質的に難易度が低いため。この実機検証結果に基づき、**動く絵文字（8個・APNG）の提供を取りやめ、
> 静止画40個セットに全面刷新**した。動く絵文字への再挑戦は、画像生成モデルの精度が
> 向上した場合に再検討する。

読者はキャラクターを事前に決める必要はない。マスタープロンプトを送ると、AIが
「動物」「丸顔・絵文字風」「人物（ちびキャラ）」の3系統でキャラクター候補A/B/Cを提案し、
読者は選ぶだけでよい（自分の画像がある場合はそれを送ってもよい）。

> **注記（人物系統の技術的留意点）**: 表情差分を複数フレーム作る際、人物は動物・丸顔キャラより
> 特徴点が多く、フレーム間で顔がブレやすい傾向がある。マスタープロンプトには
> 「シンプル・ちびキャラ風で描く」など一貫性を保つための指示を明記する。

### 2.3 40個セットの構成

`40-emoji-set-plan.json` を正本とする。1セット＝40個（すべて静止画1枚ずつ）、
4グループ構成：表情20・生活シーン10・単独アイコン3・ふきだし文字7。

| グループ | 番号 | 内容の例 |
|---|---|---|
| 表情 | 001〜020 | こんにちは・ありがとう・OK・大笑い・ごめんね・がんばる・おやすみ・びっくり 等 |
| 生活シーン | 021〜030 | スマホを見る・パソコン作業・コーヒーブレイク・読書中・お辞儀・ジャンプ 等 |
| 単独アイコン | 031〜033 | ハートマーク・星マーク・チェックマーク（キャラクターは出さない） |
| ふきだし文字 | 034〜040 | ありがとう・おつかれさま・OK！・よろしくね・ごめんね・またね・おやすみ |

内容（意味・見た目）は`40-emoji-set-plan.json`のmeaning/descriptionを書き換えれば変更できる。
grid_rows×grid_colsとitemsの数（40個）は一致させる。

### 2.4 グリッド方式による一括生成

1回の画像生成で「40個」を1枚のグリッド画像として生成し、
コード（`emoji_pipeline.py`）でマス目ごとに切り出す方式を採る（競合の40個一括生成と同じ考え方）。

- 生成：8行×5列（grid_rows×grid_cols）の1枚画像
- 切り出し：セルごとに中央配置・背景透過処理（白背景の場合は自動で透過化）を行い、180×180に統一
- 仕上げ：001番の画像からトークルームタブ画像（96×74）を生成
- レビュー：40個それぞれのプレビュー画像とチェックリスト雛形を作り、目視確認した結果
  （meaning_matches／no_semantic_duplicate／no_clipping_or_cropping／readable／
  background_transparent）がすべてtrueで埋まっていることをコードが検証する
- 梱包：レビュー済みチェックリストを検証したうえで、001〜040.png ＋ tab.pngを
  `line-emoji-set.zip`にまとめる（20MB以内を検証）。未確認・不一致があるとZIP作成を拒否する

単品修正（例：「029だけ修正」）は該当番号だけを再生成し、該当PNGとZIPだけを更新する。
40個全体は作り直さない。

### 2.5 2ルート構成

| ルート | 対象 | 技術的な流れ |
|---|---|---|
| Codexルート | Codexを使える読者 | ①マスタープロンプト送付→AIがキャラ候補A/B/Cを提案 → ②「マスター画像生成」 → ③「40個生成」（8×5のグリッド画像） → ④「zip」でemoji_pipeline.pyを実行（切り出し→レビュー→タブ画像→ZIP） |
| ChatGPTのみルート | ChatGPTのみの読者（コード実行機能が使える環境が必要） | Codexルートと同じ会話フローを、ChatGPTの「コード実行（Data Analysis）」機能を使い**同一チャット内**で完結させる |

両ルートとも、配布するキット（ZIP・プロンプト・パイプラインスクリプト）はオリジナルで新規作成する。
ChatGPTルートは「コード実行が使えるプラン・環境」が前提条件であることをページ上で明示する。
