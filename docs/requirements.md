- 操作者: ブラウザのエンドユーザー（Instagramリールから訪れる読者）

- 動的変数: なし
- 種別: Web型

  「リールにコメント → DM → オープンチャット誘導 → オプチャ内の特典まとめから受け取る」（[[tokuten-distribution-flow]]）

## 1. プロジェクト概要

Instagramリールの特典として配布する、スマートフォン最優先の1ページ完結ガイド。
「動くLINE絵文字」をCodex（コード実行ができるAIエージェント）またはChatGPT（画像生成のみ）のどちらでも
作れるように、2つのルートを1つのキットとして案内する。

競合LP（one-lp-1.com/lp/line-emoji/）の構成を参考にしつつ、配布するキットの中身は完全オリジナルで新規作成する
（競合が配布するファイルをそのまま流用しない）。

### 成功指標

| 種別 | 指標 |
|---|---|
| 定量 | 横スクロール0件（320 / 375 / 1280px）／JSエラー0件／プロンプトが全箇所ワンタップでコピー可能 |
| 定量 | キットZIPのダウンロードが正常に完了する（GitHub Pages配信・100MB制限内） |
| 定性 | Codexを持たない読者でも「ChatGPTだけ」ルートで最後まで迷わず到達できる |
| 定性 | 自分の絵がない読者も、AIが提案するキャラクター候補（A/B/C）から選ぶだけで迷わず次に進める |
| 定性 | 誇張表現・未確認の断定を含まない |

### 想定読者

AI初心者／副業・個人事業化志向／「絵が描けない」という障壁を感じている層／
Codex利用者とChatGPTのみの利用者の両方／スマートフォンでの閲覧・操作が中心。

## 2. 配布キットの仕様（このページの核）

### 2.1 LINE公式の技術仕様（LINE Creators Market・動く絵文字）

キットが生成する成果物は、以下の公式仕様を満たす必要がある。

| 項目 | 仕様 |
|---|---|
| フォーマット | APNG |
| キャンバスサイズ | 180×180px固定 |
| フレーム数 | 1個あたり5〜20フレーム |
| ループ回数 | 1〜4回（再生時間4秒を超えない範囲） |
| 再生時間 | 4秒以内 |
| ファイルサイズ | 1個あたり300KB以下 |
| 背景 | 透過必須 |
| 解像度・カラーモード | 72dpi以上・RGB |
| セット内の個数 | 「絵文字」のみのパッケージで8〜40個（1個単位で調整可） |
| メイン画像 | セットの中から4個を選ぶ（ストア掲載用） |
| トークルームタブ画像 | 96×74px を1個 |
| 提出用ZIP | 全体で20MB以内 |
| 出品 | LINE Creators Marketへの個人登録・申請は無料（審査あり） |

> 2026-09-21修正: キャンバスサイズを「320×270px以内」→「180×180px固定」に訂正
> （LINEスタンプ側の仕様と混同していた誤り。公式ガイドライン
> [creator.line.me/ja/guideline/animationemoji](https://creator.line.me/ja/guideline/animationemoji/)
> で確認済み）。あわせてセット個数・メイン画像・タブ画像の仕様を追記した。

### 2.2 制作フロー（競合の会話駆動パイプラインを踏襲）

> 2026-09-21改訂: 当初は「モチーフを選んでコピペ→表情差分を1個だけ作る」設計だったが、
> 競合プロンプト（LINE静止絵文字40個の自動生成パイプライン）と比較した結果、
> ①LINEは8〜40個の**セット**出品が前提であること、②ChatGPT/Codexの
> コード実行機能を使えば画像生成からZIP作成まで**同一チャット内で完結**できることが判明したため、
> 1個だけを手作業で作る設計から、**8個セットを会話駆動で一括生成する設計**に全面刷新した。

読者はキャラクターを事前に決める必要はない。マスタープロンプトを送ると、AIが
「動物」「丸顔・絵文字風」「人物（ちびキャラ）」の3系統でキャラクター候補A/B/Cを提案し、
読者は選ぶだけでよい（自分の画像がある場合はそれを送ってもよい）。

> **注記（人物系統の技術的留意点）**: 表情差分を複数フレーム作る際、人物は動物・丸顔キャラより
> 特徴点が多く、フレーム間で顔がブレやすい傾向がある。マスタープロンプトには
> 「シンプル・ちびキャラ風で描く」など一貫性を保つための指示を明記する。

### 2.3 8個セットの構成

`8-emoji-set-plan.json` を正本とする。1セット＝8個、1個あたり6フレーム（固定・全項目共通）。

| 番号 | 意味 |
|---|---|
| 001 | こんにちは（手を振る） |
| 002 | ありがとう（お辞儀） |
| 003 | OK・了解（うなずく） |
| 004 | 大笑い |
| 005 | ごめんね（頭を下げる） |
| 006 | がんばる（ガッツポーズ） |
| 007 | おやすみ（あくび→目を閉じる） |
| 008 | びっくり |

内容（意味・動き）は`8-emoji-set-plan.json`のmeaning/motionを書き換えれば変更できる。
frames（6固定・全項目同数が前提）・loop_count・frame_duration_msの仕様は変更しない。

### 2.4 グリッド方式による一括生成

1回の画像生成で「8個 × 6フレーム＝48マス」を1枚のグリッド画像として生成し、
コード（`emoji_pipeline.py`）でマス目ごとに切り出す方式を採る（競合の40個一括生成と同じ考え方）。

- 生成：8行（1行＝1個の絵文字）× 6列（1列＝その動きの1コマ）の1枚画像
- 切り出し：セルごとに中央配置・背景透過処理（白背景の場合は自動で透過化）を行い、180×180に統一
- 合成：行単位でAPNGに合成（`build_apng.py`のロジックを流用）
- 仕上げ：001番のフレームからトークルームタブ画像（96×74）を生成
- 梱包：001〜008.png ＋ tab.pngを`line-emoji-set.zip`にまとめる（20MB以内を検証）

単品修正（例：「003だけ修正」）は該当番号の6コマだけを小さなグリッド（1行×6列）で再生成し、
該当APNGとZIPだけを更新する。8個全体は作り直さない。

### 2.5 2ルート構成

| ルート | 対象 | 技術的な流れ |
|---|---|---|
| Codexルート | Codexを使える読者 | ①マスタープロンプト送付→AIがキャラ候補A/B/Cを提案 → ②「マスター画像生成」 → ③「グリッド生成」（8×6のグリッド画像） → ④「zip」でemoji_pipeline.pyを実行（切り出し→APNG合成→タブ画像→ZIP） |
| ChatGPTのみルート | ChatGPTのみの読者（コード実行機能が使える環境が必要） | Codexルートと同じ会話フローを、ChatGPTの「コード実行（Data Analysis）」機能を使い**同一チャット内**で完結させる |

両ルートとも、配布するキット（ZIP・プロンプト・パイプラインスクリプト）はオリジナルで新規作成する。
ChatGPTルートは「コード実行が使えるプラン・環境」が前提条件であることをページ上で明示する。

## 4. データ設計概要

## 5. セキュリティ要件

- 外部リンクはすべて `target="_blank"` + `rel="noopener noreferrer"`
- 入力フォーム・個人情報の収集なし
- 外部スクリプト・トラッカーの読み込みなし
- GitHub Pages は HTTPS 配信
- 配布キットZIPは自作コンテンツのみを含む（競合ファイルを一切含めない）
