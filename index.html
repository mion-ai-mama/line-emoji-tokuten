LINE絵文字って何？

LINEには、トークで使える「絵文字」を自分で作って
LINE Creators Marketに出品できる仕組みがあります（8〜40個の「セット」で出品）。
このガイドで作るのは動く絵文字（アニメーション）です。

AIとの会話でキャラクターを決め、
表情・生活シーン・アイコン・ふきだし文字の40種類を1セットとして一括生成する方法を、
Codexを使って紹介します。

🎨

キャラはAIが提案

プロンプトを送るだけで、AIがキャラクター候補を3つ提案。会話で選ぶだけで進みます。

🙂

40個をまとめて生成

表情・生活シーン・アイコン・ふきだし文字の40種類を、同じキャラクターのまま一括で作ります。

LINE公式仕様に自動対応

キャンバスサイズやファイルサイズなど、LINEの仕様を満たしているかキットが自動チェックします。

準備するもの

Codex（ChatGPTのデスクトップアプリに入っているコード実行AI）と、下のキット一式があれば始められます。
パソコン（Mac／Windows）が必要です。スマホ・タブレットでは動きません。
キャラクターは、プロンプトを送った後にAIが提案してくれるので、今は決めなくて大丈夫です。

必要なもの

ChatGPTの有料プラン（Plus以上）に入っていればCodexは追加課金なしで使えます。パソコン（Mac／Windows）・LINEアカウント（申請用）があればOKです。

Codexで作りはじめる

今回作る40個のセット内容

LINEの絵文字は8〜40個のセットで出品します。
このガイドでは、次の40種類（表情20・生活シーン10・単独アイコン3・ふきだし文字7）を 1セットとして作ります（あとから内容を変えることもできます）。

  • 001〜020 表情（こんにちは・ありがとう・OK・大笑い・ごめんね・がんばる など20種類）
  • 021〜030 生活シーン（スマホを見る・パソコン作業・コーヒーブレイク など10種類）
  • 031〜033 単独アイコン（ハート・星・チェックマーク）
  • 034〜040 ふきだし文字（ありがとう・おつかれさま・OK！ など7種類）

補足

40種類の内容は、キット内の 40-emoji-animated-plan.json が正本です。テーマを変えたい場合はこのファイルのmeaning・motionを書き換えてください。

Codexで作る（動く絵文字）

Codexなら、動く絵文字（APNG）40個セットが作れます。 キャラ提案から画像生成、コマの組み立て、ZIP作成まで、Codexが会話の中で一気に進めます。

公式サイトからCodexを入手する

必要なもの

ChatGPTの有料プラン（Plus以上）に入っていればCodexは追加課金なしで使えます。パソコン（Mac／Windows）が必要です。スマホやタブレットでは動きません。

  1. 上のボタンからCodexを入手し、起動する
  2. 下の「必要な3ファイルをダウンロード」からZIPを取得し、解凍した3ファイルすべてを作業フォルダに置く
  3. 下のプロンプトを全文コピーしてCodexに貼り付ける
  4. Codexが提案するキャラ候補A/B/Cから選ぶ（または自分の画像を送る）
  5. 「マスター画像生成」と送る（キャラの基準画像ができます）
  6. できあがったら、続けて「40個生成」と送る（40個を1個ずつ個別に生成します）
  7. できあがったら、続けて「zip」と送る（見分けの確認をしてからZIPが完成します）
  8. 気になる番号があれば「029だけ修正」と送る（直ったら「zip更新」と送る）

途中で許可を求められたら

画像を加工する道具が足りないときなど、「これを入れてもいいですか」と確認されることがあります。作業に必要なものを追加しているだけなので、そのまま許可して進めて大丈夫です。

途中で止まってしまったら

生成の返事が来ないまま止まってしまったり、区切りのいいところで止まってしまったりしても、壊れたわけではありません。「続けて」とだけ送れば、続きから再開できます。

あなたはこれから、動くLINE絵文字セット（40個・APNG）の制作を最後まで実行する担当です。

説明だけで終わらず、必要な場面では実際に画像生成・コード実行を行い、
最終的にダウンロード可能なZIPファイル（output/line-emoji-set.zip）まで完成させてください。

作業フォルダにある以下のファイルを使用します。

- 40-emoji-animated-plan.json（40個の構成の正本。番号・意味・動き・フレーム数・ループ設定はここから読む）
- emoji_pipeline_animated.py（帯画像の切り出し・APNG合成・レビュー・ZIP作成はこの実装を優先する）
- build_apng.py（emoji_pipeline_animated.pyが内部で使う。直接実行はしない）

40個は1枚にまとめず1個ずつ個別に画像生成します（まとめて生成すると複数個が似たポーズに
引っ張られる、直前の生成を引きずる、といった問題が過去の検証で確認されているため）。

## 仕様（LINE公式・動く絵文字）

- キャンバスサイズ：180×180px固定
- フォーマット：APNG（拡張子は.pngのまま）
- 1個あたりのフレーム数：10フレーム固定。1フレーム100ms×10＝ちょうど1.0秒のループ
- ループ回数：3回（合計3.0秒）。1ループの秒数が半端（例：1.2秒）だと審査で弾かれるため、
  フレーム数・表示時間・ループ回数は勝手に変更しない
- ファイルサイズ：1個あたり300KB以下
- 背景：透過必須
- セット内の個数：40個（今回の構成）
- トークルームタブ画像：96×74pxの静止PNGを1個

## 目・口の絶対条件：必ず守る

目は各フレームで必ず「完全に開く」か「完全に閉じる」のどちらかにする。半目・薄目・閉じかけの
中間状態は一切作らない。瞬きや開閉は1ループにつき最大1回、完全開眼⇔完全閉眼を直接切り替える。
口も同様に、必要な場合は「完成した開口」と「完成した閉口」の2状態だけを使い、閉じかけの
中間コマは作らない。滑らかにするために半目・半開きの口を補間しない。

## 最重要：新規制作の最初の応答

まだキャラクターが決まっていない場合は、手順説明だけを返してはいけません。
最初の応答で、すぐにキャラクター候補A/B/Cを3案提案してください
（「動物」「丸顔・絵文字風」「人物・ちびキャラ」の3系統で、種類・輪郭・体型・主色・線色・性格まで具体的に）。

ユーザーが「別の」と言った場合は新しい3案を、A/B/Cを選んだ場合はそのキャラクターを
以後ずっと固定して使ってください。自分の画像が送られた場合はそれを最優先します。
キャラクターの確認・承認はここ1回だけです。以後は「次に進めますか」と確認を挟まず、
完成まで自律的に進めてください。

## 毎ターン操作を判定

- 「マスター画像生成」→ 採用済みキャラクターの基準画像を1枚生成し、以後の参照として固定する
- 「40個生成」→ 画像生成ツールをちょうど40回呼び出す。1回につき必ず1個だけを描かせる
  （40個分をまとめて1回のツール呼び出しで一括生成することは禁止）。001〜040を1個ずつ順番に、
  その番号のmeaning・motionだけで生成し、【目・口の絶対条件】を厳守し、distinctness_noteを
  参照してそれまでに生成した他の番号と腕の位置・手の形・体の傾きが同じに見えないようにする。
  生成のたびにstrips/0XX.pngとして保存し、進捗を書く。これをユーザーの返信を待たずに
  1回の応答（タスク）の中で001〜040まで続けて40回実行する。あなたは長時間の自律実行が
  できるエージェントなので、途中で確認を挟んで停止しない
- 「zip」→ 画像生成は使わず、次を順に実際に実行する。
  1) python emoji_pipeline_animated.py slice-items --strips-dir strips --plan 40-emoji-animated-plan.json --out-dir output
  2) python emoji_pipeline_animated.py build --plan 40-emoji-animated-plan.json --out-dir output
  （フレーム数・キャンバスサイズ・ループ秒数・ファイルサイズが自動検査される。エラーの番号は
  「0XX修正」で再生成してやり直す）
  3) python emoji_pipeline_animated.py tab --source output/frames/001/01.png --out output/tab.png
  4) python emoji_pipeline_animated.py review --plan 40-emoji-animated-plan.json --out-dir output
  （output/review/001.png〜040.pngができる。これを実際に見て、checklist_TO_FILL.jsonの
  checks（meaning_matches / no_semantic_duplicate / eye_mouth_binary_states_only等）を
  正直にtrue/falseで埋め、observationに見た内容を書く。省略・虚偽記入は禁止）
  5) python emoji_pipeline_animated.py pack --plan 40-emoji-animated-plan.json --out-dir output --zip output/line-emoji-set.zip --review output/review/checklist_TO_FILL.json
  （packはchecklistにfalse・未記入があるとエラーで停止しZIPを作らない。エラーの番号は
  「0XX修正」で再生成し1〜5をやり直す。最大2回。直らなければ番号を挙げて案内する）
- 「029だけ修正」「015をもっと怒らせて」→ 指定番号だけをマスター画像を参照して単独で
  再生成し、strips/029.pngを上書きする（40個全体は作り直さない）。番号を複数指定された
  場合も1個ずつ個別再生成する。「もっと怒らせて」等の修正内容が添えられていれば実際に
  反映し、40-emoji-animated-plan.jsonのmotionにも書き加えて引き継ぐ。再生成した番号は
  checklistのその行をnullに戻す
- 「zip更新」→ 直近で再生成した番号だけを反映してZIPを作り直す

生成が途中で止まってしまった場合、ユーザーから「続けて」と送られたら続きから再開する
（最初からやり直さない）。画像を加工する道具が足りないと確認されたら、そのまま許可して進める。

相手はプログラミングをしない読者です。パッケージ名・ファイル名・コード上の変数名・エラー文の原文
（emoji_pipeline_animated.py、strips/001.png、no_semantic_duplicate、eye_mouth_binary_states_only等）を
そのまま出さず、日常の言葉に言い換えてください。各応答の最後に「現在／今回できたこと／次の操作」を
平易な言葉で短く示し、未実行の処理を完成と書かないでください。
LINEへのアップロードや審査申請はユーザーが行います。実行したと装わないでください。
必要な3ファイルをダウンロード（ZIP）

40個そろったら

ZIPが完成しても、そこで終わりにせず、申請前に一度は自分の目で40個を見比べてみましょう。 AIのレビューだけに任せきりにしないことで、仕上がりへの安心感も上がります。

  1. 全体をひととおり見る
    40個を並べて、キャラクターの形・色がそろっているか、同じような表情ばかりになって いないかを確認します。気になるものがあれば、「029だけ修正」「015をもっと怒らせて」 のように番号＋直したい内容を伝えると、ピンポイントで直してもらえます。
  2. LINEの仕様を満たしているか確認する
    キャンバスサイズ・ファイルサイズ・背景の透過（動く絵文字の場合はループの秒数も）は キット内のパイプラインが自動でチェックしていますが、下の「LINEへの申請方法」の 一覧と見比べておくと安心です。

LINEへの申請方法

完成したファイルは、「LINE Creators Market」で公式サイトを検索し、
個人クリエイターとして登録・申請することで出品できます（登録・申請は無料、審査があります）。
「新規登録」の画面で、「アニメーション絵文字」を選んでください （静止画の「絵文字」と間違えないよう注意してください。種類を選び直すと入力がやり直しになることがあります）。

LINE Creators Marketを開く
  • フォーマット：APNG（拡張子は.pngのまま）
  • キャンバスサイズ：180×180px固定
  • フレーム数：5〜20フレーム（キットでは10フレーム固定）
  • ループ：1ループがちょうど1・2・3・4秒のどれか（1.2秒のような半端な秒数は審査で弾かれます）。再生回数は1〜4回、合計4秒以内
  • ファイルサイズ：1個あたり300KB以下
  • 背景：透過必須
  • セット内の個数：8〜40個（1個単位で調整可）
  • メイン画像：セットの中から4個を選ぶ（ストア掲載用）
  • トークルームタブ画像：96×74pxの静止PNGを1個
  • 提出用ZIP：20MB以内

これらの数値は emoji_pipeline_animated.py（内部でbuild_apng.py）が 自動でチェックしてくれます。

うまくいかないとき

「マスター画像生成」で作った基準画像をもう一度参照するよう伝え、ブレている番号を「00X修正」で再生成してください。人物モチーフの場合は、より簡略化した「ちびキャラ」で描き直すよう伝えると安定しやすくなります。

「zip」の工程で行う目視レビュー（no_semantic_duplicateのチェック）で気づけるようになっています。指摘された番号を「0X0だけ修正」で再生成してください。それでも似てしまう場合は、40-emoji-animated-plan.jsonのmotionで、その番号だけ手の位置や小物を大きく変えると直りやすいです。

Codexルートでは「目・口は完全に開くか完全に閉じるかのどちらか」という絶対条件を指示していますが、それでも半端なコマが混ざることがあります。レビュー工程のeye_mouth_binary_states_onlyで気づけるようになっているので、指摘された番号を「0X0だけ修正」で再生成してください。

LINEの審査は、1ループの再生時間がちょうど1・2・3・4秒でないと通しません。キットは10フレーム×100ms＝ちょうど1.0秒のループで固定しているため、この数値を書き換えないかぎり起こらないはずです。もし変更していた場合は元の設定に戻してください。

キット内のパイプラインは、背景が透過されていない場合に白背景を自動で透過処理します。背景が白以外（グラデーションや模様など）の場合は、「背景を無地の白にして」と伝えて生成し直してください。

キャラクターの色数や模様の細かさを減らして生成し直してください。上限は1個あたり300KBです。パイプラインがエラーで教えてくれます。

キット内の40-emoji-animated-plan.jsonのmeaning（意味）・motion（動きの説明）を書き換えてから「40個生成」をやり直してください。

他者のキャラクターやイラストに酷似していないか、仕様（サイズ・枚数・ファイルサイズ）を満たしているかを見直してください。審査基準はLINE Creators Market公式サイトの最新情報をご確認ください。
