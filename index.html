LINE絵文字って何？

LINEには、トークで使える「絵文字」を自分で作って
LINE Creators Marketに出品できる仕組みがあります（8〜40個の「セット」で出品）。
動く絵文字（アニメーション）と動かない絵文字（静止画）の 2種類があります。

このガイドでは、AIとの会話でキャラクターを決め、
表情・生活シーン・アイコン・ふきだし文字の40種類を1セットとして一括生成する方法を紹介します。
Codexが使える人は動く絵文字、ChatGPTだけの人は静止絵文字が作れます （パソコンの有無で分かれます。詳しくは下の「準備するもの」参照）。

ChatGPTだけの人

できあがるのは静止絵文字です。ファイルのダウンロード・添付は一切不要。ChatGPTアプリだけで完結します（パソコンでもスマホでもOK）。

ChatGPTルートへ進む

今回作る40個のセット内容

LINEの絵文字は8〜40個のセットで出品します。
このガイドでは、次の40種類（表情20・生活シーン10・単独アイコン3・ふきだし文字7）を 1セットとして作ります（あとから内容を変えることもできます）。

  • 001〜020 表情（こんにちは・ありがとう・OK・大笑い・ごめんね・がんばる など20種類）
  • 021〜030 生活シーン（スマホを見る・パソコン作業・コーヒーブレイク など10種類）
  • 031〜033 単独アイコン（ハート・星・チェックマーク）
  • 034〜040 ふきだし文字（ありがとう・おつかれさま・OK！ など7種類）

補足

40種類の内容は、キット内の構成ファイルが正本です（Codexルート＝40-emoji-animated-plan.json、ChatGPTルート＝40-emoji-set-plan.json）。テーマを変えたい場合はこのファイルのmeaning・motion／descriptionを書き換えてください。

Codexで作る（動く絵文字）

Codexなら、動く絵文字（APNG）40個セットが作れます。 キャラ提案から画像生成、コマの組み立て、ZIP作成まで、Codexが会話の中で一気に進めます。

公式サイトからCodexを入手する

必要なもの

ChatGPTの有料プラン（Plus以上）に入っていればCodexは追加課金なしで使えます。パソコン（Mac／Windows）が必要です。スマホやタブレットでは動きません。パソコンがない場合は「パソコンがない人はこちら」をご利用ください（できあがるのは静止画になります）。

  1. 上のボタンからCodexを入手し、起動する
  2. 下の「必要な3ファイルをダウンロード」からZIPを取得し、解凍した3ファイルすべてを作業フォルダに置く
  3. 下のプロンプトを全文コピーしてCodexに貼り付ける
  4. Codexが提案するキャラ候補A/B/Cから選ぶ（または自分の画像を送る）
  5. 「マスター画像生成」と送る（キャラの基準画像ができます）
  6. できあがったら、続けて「40個生成」と送る（40個を1個ずつ個別に生成します）
  7. できあがったら、続けて「zip」と送る（見分けの確認をしてからZIPが完成します）
  8. 気になる番号があれば「029だけ修正」と送る（直ったら「zip更新」と送る）

途中で許可を求められたら

画像を加工する道具が足りないときなど、「これを入れてもいいですか」と確認されることがあります。作業に必要なものを追加しているだけなので、そのまま許可して進めて大丈夫です。

途中で止まってしまったら

生成の返事が来ないまま止まってしまったり、区切りのいいところで止まってしまったりしても、壊れたわけではありません。「続けて」とだけ送れば、続きから再開できます。

あなたはこれから、動くLINE絵文字セット（40個・APNG）の制作を最後まで実行する担当です。

説明だけで終わらず、必要な場面では実際に画像生成・コード実行を行い、
最終的にダウンロード可能なZIPファイル（output/line-emoji-set.zip）まで完成させてください。

作業フォルダにある以下のファイルを使用します。

- 40-emoji-animated-plan.json（40個の構成の正本。番号・意味・動き・フレーム数・ループ設定はここから読む）
- emoji_pipeline_animated.py（帯画像の切り出し・APNG合成・レビュー・ZIP作成はこの実装を優先する）
- build_apng.py（emoji_pipeline_animated.pyが内部で使う。直接実行はしない）

40個は1枚にまとめず1個ずつ個別に画像生成します（まとめて生成すると複数個が似たポーズに
引っ張られる、直前の生成を引きずる、といった問題が過去の検証で確認されているため）。

## 仕様（LINE公式・動く絵文字）

- キャンバスサイズ：180×180px固定
- フォーマット：APNG（拡張子は.pngのまま）
- 1個あたりのフレーム数：10フレーム固定。1フレーム100ms×10＝ちょうど1.0秒のループ
- ループ回数：3回（合計3.0秒）。1ループの秒数が半端（例：1.2秒）だと審査で弾かれるため、
  フレーム数・表示時間・ループ回数は勝手に変更しない
- ファイルサイズ：1個あたり300KB以下
- 背景：透過必須
- セット内の個数：40個（今回の構成）
- トークルームタブ画像：96×74pxの静止PNGを1個

## 目・口の絶対条件：必ず守る

目は各フレームで必ず「完全に開く」か「完全に閉じる」のどちらかにする。半目・薄目・閉じかけの
中間状態は一切作らない。瞬きや開閉は1ループにつき最大1回、完全開眼⇔完全閉眼を直接切り替える。
口も同様に、必要な場合は「完成した開口」と「完成した閉口」の2状態だけを使い、閉じかけの
中間コマは作らない。滑らかにするために半目・半開きの口を補間しない。

## 最重要：新規制作の最初の応答

まだキャラクターが決まっていない場合は、手順説明だけを返してはいけません。
最初の応答で、すぐにキャラクター候補A/B/Cを3案提案してください
（「動物」「丸顔・絵文字風」「人物・ちびキャラ」の3系統で、種類・輪郭・体型・主色・線色・性格まで具体的に）。

ユーザーが「別の」と言った場合は新しい3案を、A/B/Cを選んだ場合はそのキャラクターを
以後ずっと固定して使ってください。自分の画像が送られた場合はそれを最優先します。
キャラクターの確認・承認はここ1回だけです。以後は「次に進めますか」と確認を挟まず、
完成まで自律的に進めてください。

## 毎ターン操作を判定

- 「マスター画像生成」→ 採用済みキャラクターの基準画像を1枚生成し、以後の参照として固定する
- 「40個生成」→ 画像生成ツールをちょうど40回呼び出す。1回につき必ず1個だけを描かせる
  （40個分をまとめて1回のツール呼び出しで一括生成することは禁止）。001〜040を1個ずつ順番に、
  その番号のmeaning・motionだけで生成し、【目・口の絶対条件】を厳守し、distinctness_noteを
  参照してそれまでに生成した他の番号と腕の位置・手の形・体の傾きが同じに見えないようにする。
  生成のたびにstrips/0XX.pngとして保存し、進捗を書く。これをユーザーの返信を待たずに
  1回の応答（タスク）の中で001〜040まで続けて40回実行する。あなたは長時間の自律実行が
  できるエージェントなので、途中で確認を挟んで停止しない
- 「zip」→ 画像生成は使わず、次を順に実際に実行する。
  1) python emoji_pipeline_animated.py slice-items --strips-dir strips --plan 40-emoji-animated-plan.json --out-dir output
  2) python emoji_pipeline_animated.py build --plan 40-emoji-animated-plan.json --out-dir output
  （フレーム数・キャンバスサイズ・ループ秒数・ファイルサイズが自動検査される。エラーの番号は
  「0XX修正」で再生成してやり直す）
  3) python emoji_pipeline_animated.py tab --source output/frames/001/01.png --out output/tab.png
  4) python emoji_pipeline_animated.py review --plan 40-emoji-animated-plan.json --out-dir output
  （output/review/001.png〜040.pngができる。これを実際に見て、checklist_TO_FILL.jsonの
  checks（meaning_matches / no_semantic_duplicate / eye_mouth_binary_states_only等）を
  正直にtrue/falseで埋め、observationに見た内容を書く。省略・虚偽記入は禁止）
  5) python emoji_pipeline_animated.py pack --plan 40-emoji-animated-plan.json --out-dir output --zip output/line-emoji-set.zip --review output/review/checklist_TO_FILL.json
  （packはchecklistにfalse・未記入があるとエラーで停止しZIPを作らない。エラーの番号は
  「0XX修正」で再生成し1〜5をやり直す。最大2回。直らなければ番号を挙げて案内する）
- 「029だけ修正」「015をもっと怒らせて」→ 指定番号だけをマスター画像を参照して単独で
  再生成し、strips/029.pngを上書きする（40個全体は作り直さない）。番号を複数指定された
  場合も1個ずつ個別再生成する。「もっと怒らせて」等の修正内容が添えられていれば実際に
  反映し、40-emoji-animated-plan.jsonのmotionにも書き加えて引き継ぐ。再生成した番号は
  checklistのその行をnullに戻す
- 「zip更新」→ 直近で再生成した番号だけを反映してZIPを作り直す

生成が途中で止まってしまった場合、ユーザーから「続けて」と送られたら続きから再開する
（最初からやり直さない）。画像を加工する道具が足りないと確認されたら、そのまま許可して進める。

相手はプログラミングをしない読者です。パッケージ名・ファイル名・コード上の変数名・エラー文の原文
（emoji_pipeline_animated.py、strips/001.png、no_semantic_duplicate、eye_mouth_binary_states_only等）を
そのまま出さず、日常の言葉に言い換えてください。各応答の最後に「現在／今回できたこと／次の操作」を
平易な言葉で短く示し、未実行の処理を完成と書かないでください。
LINEへのアップロードや審査申請はユーザーが行います。実行したと装わないでください。
必要な3ファイルをダウンロード（ZIP）

```python
#!/usr/bin/env python3
"""LINE静止絵文字セット（40個）を、1枚のグリッド画像から一括処理するパイプライン。"""
from __future__ import annotations

import argparse
import json
import sys
import zipfile
from pathlib import Path

from PIL import Image

CANVAS_SIZE = (180, 180)
USABLE_SIZE = 152
BG_COLOR_TOLERANCE = 18
MAX_ZIP_SIZE_BYTES = 20 * 1024 * 1024
MAX_FILE_SIZE_BYTES = 1024 * 1024
TAB_SIZE = (96, 74)
REVIEW_CHECK_NAMES = (
    "meaning_matches",
    "no_semantic_duplicate",
    "no_clipping_or_cropping",
    "readable",
    "background_transparent",
)


def load_plan(plan_path: Path) -> dict:
    plan = json.loads(plan_path.read_text(encoding="utf-8"))
    expected = plan["grid_rows"] * plan["grid_cols"]
    if len(plan["items"]) != expected:
        raise SystemExit(
            f"itemsの数（{len(plan['items'])}）がgrid_rows×grid_cols（{expected}）と一致しません。"
        )
    return plan


def remove_near_background(image: Image.Image, bg_color=(255, 255, 255)) -> Image.Image:
    image = image.convert("RGBA")
    pixels = list(image.getdata())
    has_alpha_variance = any(p[3] < 250 for p in pixels)
    if has_alpha_variance:
        return image
    new_pixels = [
        (r, g, b, 0)
        if abs(r - bg_color[0]) <= BG_COLOR_TOLERANCE
        and abs(g - bg_color[1]) <= BG_COLOR_TOLERANCE
        and abs(b - bg_color[2]) <= BG_COLOR_TOLERANCE
        else (r, g, b, a)
        for r, g, b, a in pixels
    ]
    image.putdata(new_pixels)
    return image


def crop_to_content(image: Image.Image) -> Image.Image:
    bbox = image.getbbox()
    return image.crop(bbox) if bbox else image


def center_on_canvas(image: Image.Image) -> Image.Image:
    image.thumbnail((USABLE_SIZE, USABLE_SIZE), Image.LANCZOS)
    canvas = Image.new("RGBA", CANVAS_SIZE, (0, 0, 0, 0))
    x = (CANVAS_SIZE[0] - image.width) // 2
    y = (CANVAS_SIZE[1] - image.height) // 2
    canvas.paste(image, (x, y), image)
    return canvas


def slice_grid(grid_path: Path, plan: dict, out_dir: Path) -> None:
    grid = Image.open(grid_path).convert("RGBA")
    items = plan["items"]
    cols = plan["grid_cols"]
    rows = plan["grid_rows"]
    cell_w = grid.width / cols
    cell_h = grid.height / rows
    out_dir.mkdir(parents=True, exist_ok=True)
    for index, item in enumerate(items):
        row, col = divmod(index, cols)
        box = (
            round(col * cell_w),
            round(row * cell_h),
            round((col + 1) * cell_w),
            round((row + 1) * cell_h),
        )
        cell = grid.crop(box)
        cell = remove_near_background(cell)
        cell = crop_to_content(cell)
        cell = center_on_canvas(cell)
        output_path = out_dir / f"{item['number']}.png"
        cell.save(output_path)
        size = output_path.stat().st_size
        if size > MAX_FILE_SIZE_BYTES:
            raise SystemExit(
                f"{item['number']}.pngが上限を超えています: {size / 1024:.1f}KB"
                f"（上限 {MAX_FILE_SIZE_BYTES / 1024:.0f}KB。色数を減らして再生成してください）"
            )
    print(f"✅ 切り出し完了: {rows}行×{cols}列 → {len(items)}個 → {out_dir}")


def make_tab(source_path: Path, out_path: Path) -> None:
    image = Image.open(source_path).convert("RGBA")
    content = crop_to_content(image) or image
    scale = min(TAB_SIZE[0] / content.width, TAB_SIZE[1] / content.height)
    resized = content.resize((max(1, round(content.width * scale)), max(1, round(content.height * scale))), Image.LANCZOS)
    canvas = Image.new("RGBA", TAB_SIZE, (0, 0, 0, 0))
    x = (TAB_SIZE[0] - resized.width) // 2
    y = (TAB_SIZE[1] - resized.height) // 2
    canvas.paste(resized, (x, y), resized)
    canvas.save(out_path)
    print(f"✅ タブ画像を作成: {out_path}")


def make_review(plan: dict, out_dir: Path) -> None:
    review_dir = out_dir / "review"
    review_dir.mkdir(parents=True, exist_ok=True)
    checklist = {"items": []}
    for item in plan["items"]:
        source_path = out_dir / f"{item['number']}.png"
        if not source_path.exists():
            raise SystemExit(f"レビュー画像を作れません。先にsliceを実行してください: {item['number']}")
        Image.open(source_path).convert("RGBA").save(review_dir / f"{item['number']}.png")
        checklist["items"].append(
            {
                "number": item["number"],
                "meaning": item["meaning"],
                "description": item["description"],
                "checks": {name: None for name in REVIEW_CHECK_NAMES},
                "observation": "",
            }
        )
    checklist_path = review_dir / "checklist_TO_FILL.json"
    checklist_path.write_text(json.dumps(checklist, ensure_ascii=False, indent=2), encoding="utf-8")
    print(f"✅ レビュー用画像とチェックリスト雛形を作成: {review_dir}")


def load_checklist(checklist_path: Path, plan: dict) -> dict:
    checklist = json.loads(checklist_path.read_text(encoding="utf-8"))
    by_number = {it["number"]: it for it in checklist.get("items", [])}
    plan_numbers = [item["number"] for item in plan["items"]]
    missing = [n for n in plan_numbers if n not in by_number]
    if missing:
        raise SystemExit(f"チェックリストに番号が足りません: {missing}")
    failed = []
    for number in plan_numbers:
        entry = by_number[number]
        checks = entry.get("checks", {})
        for name in REVIEW_CHECK_NAMES:
            if checks.get(name) is not True:
                failed.append(f"{number}: {name} が true になっていません（現在: {checks.get(name)!r}）")
        if not entry.get("observation", "").strip():
            failed.append(f"{number}: observationが空です（実際に見た内容を書くこと）")
    if failed:
        raise SystemExit(
            "チェックリストが未完了、または不一致が見つかりました。ZIPを作成できません:\n"
            + "\n".join(f"  - {f}" for f in failed)
        )
    return checklist


def pack(plan: dict, out_dir: Path, zip_path: Path, review_path: Path) -> None:
    load_checklist(review_path, plan)
    files = [out_dir / f"{item['number']}.png" for item in plan["items"]]
    files.append(out_dir / "tab.png")
    missing = [f for f in files if not f.exists()]
    if missing:
        raise SystemExit(f"ZIPに入れるファイルが見つかりません: {missing}")
    zip_path.parent.mkdir(parents=True, exist_ok=True)
    with zipfile.ZipFile(zip_path, "w", zipfile.ZIP_DEFLATED) as zf:
        for f in files:
            zf.write(f, arcname=f.name)
    size = zip_path.stat().st_size
    if size > MAX_ZIP_SIZE_BYTES:
        raise SystemExit(f"ZIPが上限を超えています: {size / 1024 / 1024:.1f}MB（上限 20MB）")
    print(f"✅ ZIP作成完了: {zip_path}（{size / 1024:.0f}KB）")


def parse_args(argv: list[str]) -> argparse.Namespace:
    parser = argparse.ArgumentParser(description=__doc__)
    sub = parser.add_subparsers(dest="command", required=True)

    p_slice = sub.add_parser("slice")
    p_slice.add_argument("--grid", type=Path, required=True)
    p_slice.add_argument("--plan", type=Path, required=True)
    p_slice.add_argument("--out-dir", type=Path, required=True)

    p_tab = sub.add_parser("tab")
    p_tab.add_argument("--source", type=Path, required=True)
    p_tab.add_argument("--out", type=Path, required=True)

    p_review = sub.add_parser("review")
    p_review.add_argument("--plan", type=Path, required=True)
    p_review.add_argument("--out-dir", type=Path, required=True)

    p_pack = sub.add_parser("pack")
    p_pack.add_argument("--plan", type=Path, required=True)
    p_pack.add_argument("--out-dir", type=Path, required=True)
    p_pack.add_argument("--zip", type=Path, required=True)
    p_pack.add_argument("--review", type=Path, required=True)

    p_all = sub.add_parser("all")
    p_all.add_argument("--grid", type=Path, required=True)
    p_all.add_argument("--plan", type=Path, required=True)
    p_all.add_argument("--out-dir", type=Path, required=True)

    return parser.parse_args(argv)


def main(argv: list[str]) -> int:
    args = parse_args(argv)
    if args.command == "slice":
        slice_grid(args.grid, load_plan(args.plan), args.out_dir)
    elif args.command == "tab":
        make_tab(args.source, args.out)
    elif args.command == "review":
        make_review(load_plan(args.plan), args.out_dir)
    elif args.command == "pack":
        pack(load_plan(args.plan), args.out_dir, args.zip, args.review)
    elif args.command == "all":
        plan = load_plan(args.plan)
        slice_grid(args.grid, plan, args.out_dir)
        make_tab(args.out_dir / f"{plan['items'][0]['number']}.png", args.out_dir / "tab.png")
        make_review(plan, args.out_dir)
    return 0


if __name__ == "__main__":
    sys.exit(main(sys.argv[1:]))
```

保存できたら、次の仕様・進め方に沿って制作を進めてください。

## 仕様（LINE公式・静止絵文字）

- キャンバスサイズ：180×180px固定
- ファイル形式：PNG（静止画。アニメーションではない）
- ファイルサイズ：1個あたり1MB以下
- 背景：透過必須
- セット内の個数：40個（今回の構成）
- トークルームタブ画像：96×74pxを1個

## 最重要：新規制作の最初の応答

まだキャラクターが決まっていない場合は、手順説明だけを返してはいけません。
最初の応答で、すぐにキャラクター候補A/B/Cを3案提案してください
（「動物」「丸顔・絵文字風」「人物・ちびキャラ」の3系統で、種類・輪郭・体型・主色・線色・性格まで具体的に）。

ユーザーが「別の」と言った場合は新しい3案を、A/B/Cを選んだ場合はそのキャラクターを
以後ずっと固定して使ってください。自分の画像が送られた場合はそれを最優先します。

## 毎ターン操作を判定

- 「マスター画像生成」→ 採用済みキャラクターの基準画像を1枚、実際に生成し、以後の参照として固定する
- 「40個生成」→ 40-emoji-set-plan.jsonのitems（40個）に沿って、キャラの見た目を保ったまま
  1枚の画像（8行×5列）として生成し、grid.pngに保存する。031〜033はキャラを出さずアイコンのみ、
  034〜040は吹き出し＋文字のみにする。distinctness_noteを参照し、紛らわしいペアを混同しない。
  時間がかかっても40個描き終えるまで応答を止めない（初心者は途中で止まると「できない」と
  誤解してやめてしまうため）。本当に続行できない技術的理由がある場合のみ途中で止めて理由を伝える
- 「zip」→ 画像生成機能は使わず、次を順に実際に実行する。
  1) python emoji_pipeline.py slice --grid grid.png --plan 40-emoji-set-plan.json --out-dir output
  2) python emoji_pipeline.py tab --source output/001.png --out output/tab.png
  3) python emoji_pipeline.py review --plan 40-emoji-set-plan.json --out-dir output
  （output/review/001.png〜040.pngができる。これを実際に見て、checklist_TO_FILL.jsonの
  checks（meaning_matches / no_semantic_duplicate等）を正直にtrue/falseで埋め、
  observationに見た内容を書く。省略・虚偽記入は禁止）
  4) python emoji_pipeline.py pack --plan 40-emoji-set-plan.json --out-dir output --zip output/line-emoji-set.zip --review output/review/checklist_TO_FILL.json
  （packはchecklistにfalse・未記入があるとエラーで停止しZIPを作らない。エラーの番号は
  「00X修正」で再生成し3〜4をやり直す。最大2回。直らなければ番号を挙げて案内する）
- 「029だけ修正」「015をもっと怒らせて」→ 指定番号だけをマスター画像を参照して単独で
  再生成し、output/029.pngを上書きする（40個全体は作り直さない）。番号を複数指定された
  場合も1個ずつ個別再生成する。「もっと怒らせて」等の修正内容が添えられていれば実際に
  反映し、40-emoji-set-plan.jsonのdescriptionにも書き加えて引き継ぐ。再生成した番号は
  checklistのその行をnullに戻す
- 「zip更新」→ 直近で再生成した番号だけを反映してZIPを作り直す

生成が途中で止まってしまった場合、ユーザーから「続けて」と送られたら続きから再開する
（最初からやり直さない）。

相手はプログラミングをしない読者です。ファイル名・コード上の変数名・エラー文の原文
（emoji_pipeline.py、grid.png、no_semantic_duplicate、ModuleNotFoundError等）を
そのまま出さず、日常の言葉に言い換えてください。各応答の最後に「現在／今回できたこと／次の操作」を
平易な言葉で短く示し、未実行の処理を完成と書かないでください。
LINEへのアップロードや審査申請はユーザーが行います。実行したと装わないでください。

40個そろったら

ZIPが完成しても、そこで終わりにせず、申請前に一度は自分の目で40個を見比べてみましょう。 AIのレビューだけに任せきりにしないことで、仕上がりへの安心感も上がります。

  1. 全体をひととおり見る
    40個を並べて、キャラクターの形・色がそろっているか、同じような表情ばかりになって いないかを確認します。気になるものがあれば、「029だけ修正」「015をもっと怒らせて」 のように番号＋直したい内容を伝えると、ピンポイントで直してもらえます。
  2. LINEの仕様を満たしているか確認する
    キャンバスサイズ・ファイルサイズ・背景の透過（動く絵文字の場合はループの秒数も）は キット内のパイプラインが自動でチェックしていますが、下の「LINEへの申請方法」の 一覧と見比べておくと安心です。

LINEへの申請方法

完成したファイルは、「LINE Creators Market」で公式サイトを検索し、
個人クリエイターとして登録・申請することで出品できます（登録・申請は無料、審査があります）。
「新規登録」の画面で、動く絵文字なら「アニメーション絵文字」、静止絵文字なら「絵文字」を 選んでください。種類を選び直すと入力がやり直しになることがあるので注意してください。

Codexルート（動く絵文字）の仕様

  • フォーマット：APNG（拡張子は.pngのまま）
  • キャンバスサイズ：180×180px固定
  • フレーム数：5〜20フレーム（キットでは10フレーム固定）
  • ループ：1ループがちょうど1・2・3・4秒のどれか（1.2秒のような半端な秒数は審査で弾かれます）。再生回数は1〜4回、合計4秒以内
  • ファイルサイズ：1個あたり300KB以下
  • 背景：透過必須
  • セット内の個数：8〜40個（1個単位で調整可）
  • メイン画像：セットの中から4個を選ぶ（ストア掲載用）
  • トークルームタブ画像：96×74pxの静止PNGを1個
  • 提出用ZIP：20MB以内

これらの数値は emoji_pipeline_animated.py（内部でbuild_apng.py）が 自動でチェックしてくれます。

ChatGPTルート（静止絵文字）の仕様

  • フォーマット：PNG（静止画）
  • キャンバスサイズ：180×180px固定
  • ファイルサイズ：1個あたり1MB以下
  • 背景：透過必須
  • セット内の個数：8〜40個（1個単位で調整可）
  • メイン画像：セットの中から4個を選ぶ（ストア掲載用）
  • トークルームタブ画像：96×74pxを1個
  • 提出用ZIP：20MB以内

これらの数値は emoji_pipeline.py が自動でチェックしてくれます。

うまくいかないとき

お使いのプラン・環境ではコード実行（Data Analysis／Code Interpreter）が使えない可能性があります。コード実行が使えるプランをご確認いただくか、パソコンがあれば「Codexで作る」ルートに切り替えてください（Codexルートは動く絵文字になります。静止絵文字ではなく動く絵文字にしたい場合はこちらがおすすめです）。

「マスター画像生成」で作った基準画像をもう一度参照するよう伝え、ブレている番号を「00X修正」で再生成してください。人物モチーフの場合は、より簡略化した「ちびキャラ」で描き直すよう伝えると安定しやすくなります。

「zip」の工程で行う目視レビュー（no_semantic_duplicateのチェック）で気づけるようになっています。指摘された番号を「0X0だけ修正」で再生成してください。それでも似てしまう場合は、構成ファイル（Codexルートは40-emoji-animated-plan.json、ChatGPTルートは40-emoji-set-plan.json）のmotion／descriptionで、その番号だけ手の位置や小物を大きく変えると直りやすいです。

Codexルートでは「目・口は完全に開くか完全に閉じるかのどちらか」という絶対条件を指示していますが、それでも半端なコマが混ざることがあります。レビュー工程のeye_mouth_binary_states_onlyで気づけるようになっているので、指摘された番号を「0X0だけ修正」で再生成してください。

LINEの審査は、1ループの再生時間がちょうど1・2・3・4秒でないと通しません。キットは10フレーム×100ms＝ちょうど1.0秒のループで固定しているため、この数値を書き換えないかぎり起こらないはずです。もし変更していた場合は元の設定に戻してください。

キット内のパイプラインは、背景が透過されていない場合に白背景を自動で透過処理します。背景が白以外（グラデーションや模様など）の場合は、「背景を無地の白にして」と伝えて生成し直してください。

キャラクターの色数や模様の細かさを減らして生成し直してください。上限はCodexルート（動く絵文字）が1個300KB、ChatGPTルート（静止絵文字）が1個1MBです。パイプラインがエラーで教えてくれます。

キット内の構成ファイル（Codexルートは40-emoji-animated-plan.json、ChatGPTルートは40-emoji-set-plan.json）のmeaning（意味）・motion／description（動き・見た目の説明）を書き換えてから「40個生成」をやり直してください。

他者のキャラクターやイラストに酷似していないか、仕様（サイズ・枚数・ファイルサイズ）を満たしているかを見直してください。審査基準はLINE Creators Market公式サイトの最新情報をご確認ください。
